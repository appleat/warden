# 2026-10-23

## 完成：GoServerMgr —— Go + Gin 的 Linux 服务器管理系统（P0-P6 全量首版）

**架构**：单二进制（前端 `go:embed` 进 Go 可执行文件），Gin + GORM + SQLite（glebarez/sqlite，纯 Go 免 CGO）。
开发环境 Windows，产物交叉编译到 linux/amd64、arm64。

**目录**
- `cmd/server/main.go` 入口：配置→日志→DB→采集器→监控调度→路由→优雅关闭
- `internal/config` YAML + `GSM_` 环境变量覆盖；JWT 密钥缺失时自动生成 `data/jwt.key`
- `internal/store` 模型与迁移（User/AuditLog/Monitor/MonitorResult/SSHHost/Setting）
- `internal/auth` JWT + bcrypt + 登录失败锁定（5 次/15 分钟）+ TOTP
- `internal/middleware` 鉴权、RBAC、审计（异步写库）、登录限流、Recovery
- `internal/metrics` gopsutil 采集，1s 采样 + 180 点环形历史
- `internal/platform/docker` Docker Engine API（懒连接、可用性探测、容器 CRUD/stats/logs/exec、镜像/卷/网络）
- `internal/filemgr` 路径沙箱 + zip/tar 压缩解压（zip slip 防护）
- `internal/system` 防火墙三驱动（ufw/firewalld/iptables）+ 30s 未确认自动回滚、PTY（unix）/ SSH 终端
- `internal/monitor` 健康检查调度 + 结果聚合 + Webhook 告警（企微/钉钉/飞书自动适配）
- `internal/api` 路由与 handler，WebSocket：`/ws/metrics`、`/ws/containers/:id/logs|exec`、`/ws/terminal/local|ssh`
- `web/` Vue3 + TS + Vite + Element Plus + ECharts + xterm

**关键约定**
- 统一响应 `{code,msg,data}`，code=0 成功，非 0 与 HTTP 状态码一致
- 权限三级 admin > operator > viewer，写操作要求 operator
- WebSocket 鉴权用 query `token`（浏览器无法设置 Header）
- WS 控制提示走 `\x00NOTICE:` 前缀，前端渲染成浮层而非写入终端
- 前端 token 存 localStorage，同时服务端下发 httpOnly cookie

**踩过的坑**
- Go regexp 不支持 `\u4e00` 转义 → 用 `\p{Han}`，否则 MustCompile 直接 panic（已加单元测试覆盖）
- gopsutil `cpu.Percent` 基于上次调用差值，一次采样里不能连续调用两次（否则 per-core 全 0）
- creack/pty 不支持 Windows → pty 用 build tag 拆分，Windows 返回友好提示走 NOTICE 浮层
- `go build` 会嵌入 `web/dist`，必须先在 web 目录 vite build

**验证**：`go test ./...` 通过（filemgr/secure/system）；curl 冒烟通过鉴权/看板/容器/文件/监控/审计；Chrome 无头截图逐页核对，无前端报错。

**运行**：`./bin/goservermgr.exe`（默认 :8080，首访引导建号）。

## 追加：多主机支持（v1.1.0，Agent 模式）

**方案选择**：Agent 模式而非 SSH 隧道。同一份二进制 `-mode agent` 即被管端，控制端把
`/api`、`/ws` 按 `?host=<id>` 用 `httputil.ReverseProxy` 转发到 `http://agent/agent/...`。
选择理由：Docker / 文件 / 防火墙 / 终端全部复用现有 handler，无需为远程重写；SSH 方案要搞
socket 转发 + SFTP，且指标与日志流体验差。

**新增/改动**
- `internal/store`：`Host` 模型（kind=local|agent，Token 用 AES 加密落库），`EnsureLocalHost()` 播种本机记录
- `internal/fleet`：主机注册表——代理构造（路径加 `/agent` 前缀、注入 `X-Agent-Token`、剥掉
  `host`/`token` 参数、改写 `Origin`）、令牌加解密、20s 轮询探测、`InstallCommand()` 生成部署命令
- `internal/middleware/proxy.go`：`HostProxy` 中间件，`?host=` 为空/本机则 `c.Next()` 走本地逻辑
- `internal/api/agent.go`：`NewAgentRouter` 复用原有 handler，`/agent` 前缀 + 静态令牌鉴权
- `internal/api/hosts.go`：主机 CRUD、探测、令牌重置
- `internal/api/api.go`：路由拆成两组——控制端组（auth/hosts/ssh/monitors/audit）与
  主机组（dashboard/docker/containers/files/system，挂 `HostProxy`）
- 前端 `web/src/hosts.ts` + `Hosts.vue` + 顶栏主机切换器；`api.ts` 按 `HOST_SCOPED` 前缀自动注入 `host`，
  `wsURL` 一律追加 `host`

**踩过的坑**
- WS 代理最初 403：Agent 的 `upgrader.CheckOrigin` 拿 `Origin` 和 `r.Host` 比对，代理后 Host 变成了
  Agent 地址 → 在 ReverseProxy 的 Director 里同步改写 `Origin` 才通过（不能直接放宽 CheckOrigin）
- Windows 上 `rm -rf data` 被工作区安全策略拦截，联调改用 `GSM_DATA_DIR=./tmpdata` 起独立实例
- 测试里 `store.Open` 用完必须 `sqlDB.Close()`，否则 `t.TempDir()` 清理在 Windows 上失败

**验证**：`go test ./...` 全绿（新增 fleet 6 个用例：路径重写/令牌注入/参数不泄漏/离线 502/探测/安装命令）；
本地起 server(:8080)+agent(:8090) 双实例，代理看板、文件列表、下载、主机切换、WS 指标流、WS 终端全部通；
Chrome 截图零 console 错误。linux/amd64 + arm64 交叉编译通过。
部署：`deploy/install-agent.sh` 一键把目标机装成 `goservermgr-agent` 服务。

## 修复：文件管理「上一级」在 Windows 盘符根报 `open D:\D:`

**根因**（两层叠加，都在 Windows 上才暴露）：
1. 前端 `up()` 用正则 `path.replace(/[\\/][^\\/]+$/,'')` 求父路径，`D:/dev` → `D:`；后端 `filepath.IsAbs("D:")`
   为 false（盘符相对路径），被当成相对路径拼到根目录下 → `filepath.Join("D:\", "D:")` = `D:\D:` → 非法路径。
2. `/api/files` 返回的 `root` 直接用 `Files.Root()`（OS 原生，`D:\`），而 `path` 走 `displayPath()`（`D:/`），
   两边永远不相等 → 根目录时「上一级」不会禁用，且面包屑盘符段 path 是 `D:` 同样踩坑。

**改动**
- `internal/filemgr`：`Resolve` 把 `X:`（单盘符）补成 `X:/`；抽出 `withinRoot()`，Windows 下比较前统一小写
  （路径大小写不敏感，原先大小写不同会被误判越界）；新增 `RootDisplay()` 返回 `/` 分隔的根目录
- `internal/api/files.go`：`root`/`parent` 统一用 `RootDisplay()`，`parent` 在根目录时钳制为自己；
  `agent.go` / `dashboard.go` / `hosts.go` 的 `file_root` 也改用 `RootDisplay()`
- `web/src/views/Files.vue`：新增 `normPath()` / `parentOf()` / `atRoot`，`up()` 优先用后端返回的 `parent`；
  面包屑识别 `^[A-Za-z]:/` 盘符前缀，盘符段 path 传 `D:/` 而不是 `D:`
- 新增 `TestResolveWindowsDriveRoot`（非 Windows 自动 skip）

**验证**：`go test ./...` 全绿、`go vet` 干净；agent 接口 `path=D:` / `D:/` / `D:/dev` 均返回 `path=D:/`、`parent=D:/`；
CDP 驱动无头 Chrome 实机点验——根目录「上一级」禁用、进子目录后可点、点完回到 `D:/` 且无错误提示。

**测试手法备忘**：Chrome 无头 + `--remote-debugging-port` 必须在**同一次 PowerShell 调用**里启动并跑 node 脚本，
调用结束进程会被回收；node 22 自带全局 `WebSocket`，可直接走 CDP，无需装 puppeteer。
