## 修复：主机管理页「复制」在非 HTTPS 下失败

**现象**：主机管理页复制「访问令牌 / 启动命令 / 写入配置」时提示「复制失败，请手动选择文本」。

**根因**：`navigator.clipboard` **只在安全上下文（HTTPS 或 localhost）下存在**。
面板部署在内网、用 `http://192.168.x.x:8080` 访问时它是 `undefined`，
原代码 `await navigator.clipboard.writeText()` 直接抛异常 → 走 catch 提示失败。

**改法**
- `web/src/utils.ts` 新增 `copyText(text): Promise<boolean>`：
  先判断 `navigator.clipboard && window.isSecureContext` 才用 Clipboard API，
  失败或非安全上下文一律兜底到 `legacyCopy()`（临时 textarea + `document.execCommand('copy')`）。
  textarea 放 `position:fixed; left:-9999px` 避免页面滚动/闪烁；显式 `setSelectionRange` 兼容 iOS Safari。
- `views/Hosts.vue` 的 `copy()` 改成调 `copyText()`，按返回值提示。
- 放到 `utils.ts` 而不是写在 Hosts.vue 里，后面其它页面要用直接引。

**经验**：前端做复制功能**不能只用 `navigator.clipboard`**，必须带 `execCommand` 兜底，
否则内网 HTTP 部署一律不可用。同类需求直接复用 `utils.ts` 的 `copyText`。

## 网站监控：新增启动 / 停止

**需求**：监控列表每个任务加启动/停止，不用进编辑弹窗改「启用」开关。

**后端**
- `POST /api/monitors/:id/toggle`（`RequireRole(operator)`），body `{"enabled":bool}`，
  只改 `Monitor.Enabled`，历史记录与配置全部保留；写审计「启动/停止监控 xxx」。
- `monitor.Service.SetEnabled(id, enabled)`：**只在启动时**重置运行时态（状态回 `unknown`、
  `Fails=0`、`LastRun` 归零让任务立刻跑一次）。停止时**什么都不做**——
  巡检 `loop()` 本来就只扫 `enabled=true`，界面上的「已停止」由 `View` 依据 `enabled` 推导。
- `View` / `ViewLive` 拆开：`View` 对停用任务强制返回 `status=paused`；
  `ViewLive` 不强制，供手动「检测」使用。**否则停用状态下点检测，成功结果会被 paused 覆盖**，
  前端会误报「检测失败」。
- 进程重启后内存态为空，但停用任务仍显示 `paused`（以库里的 enabled 为准，不依赖内存）。

**前端**（`views/Monitor.vue`）
- 操作列第一位加「停止 / 启动」链接按钮（停止=info 灰、启动=success 绿），操作列宽 230 → 276。
- `statusText` 增加 `paused → 已停止`，`statusType` 归为 info（灰标签）；站点前的状态点保持默认灰。
- 顶部汇总只统计启用的任务（`monitorSummary` 原本就 `WHERE enabled = true`），停止后自动不计入。

**验证**：新增 `internal/monitor/monitor_test.go` 的 `TestSetEnabledAndView`，
覆盖「初始 unknown / 停用后 View=paused 但 ViewLive 保留真实状态 / 启动后重置失败计数与 LastRun /
无内存态时仍显示 paused」。`go vet` / `go test ./...` 全绿，`vite build` 通过，二进制重出。

## 品牌标识（Logo）

产出在 `assets/logo/`：
- `warden-mark.svg` 512×512 圆角图标（主用）
- `warden-logo.svg` / `warden-logo-dark.svg` 横版组合（浅底 / 深底）
- `warden-mark-512.png`、`warden-mark-256.png`（透明背景）
- `warden-preview.png` 品牌预览页（各尺寸 + 深色 + 色板）

**设计**：盾牌 = 看守（Warden），盾内 `>_` 终端提示符 = 服务器运维。
渐变取自项目品牌色 `--brand: #3B63E8`（#6C8CFF → #3B63E8 → #2440B4），
盾牌面用 `#FFFFFF → #E2EAFF` 微渐变，文字色沿用 `--ink: #1C2434`。

**踩坑 1（SVG，重要）**：给「横线」路径（如 `M280 328 H328`）套
`<linearGradient>` 默认的 `objectBoundingBox` 时，**包围盒高度为 0 → 渐变退化 → 整条线不渲染**。
表现是「下划线凭空消失」，且不报任何错。改成 `gradientUnits="userSpaceOnUse"` + 绝对坐标即可。

**踩坑 2（headless Chrome 截图）**：
- `--screenshot=` / `--user-data-dir=` 必须传 **Windows 路径**（`D:/...`），传 Git Bash 的 `/d/...` 会
  「系统找不到指定的路径」，而且命令退出码是 0，很容易以为成功。
- `--window-size` 有最小值（约 500），**小尺寸截出来的其实是左上角被裁的一块**：
  圆角图标的左上角全是透明区，于是 32/64/128 的 PNG 只有一两百字节（空白）。
  小尺寸 PNG 只能靠大图缩放，别指望用 `--window-size=32,32` 直接截。
- 要透明底加 `--default-background-color=00000000`；清晰度用 `--force-device-scale-factor=2`；
  等渲染完成加 `--virtual-time-budget=3000`。

## 二进制体积分析（44.3 MB → 31.4 MB）

起因：`bin/` 里的产物 44.3 MB，用户问怎么变小。结论是**我手敲的 `go build` 漏了 `-s -w`**——
`Makefile` 和 `build.ps1` 本来就带，`dist/` 里的一直是 31 MB 左右。

**ELF 段实测（linux/amd64，未 strip，44.25 MB）**
| 段 | 大小 | 说明 |
|---|---|---|
| `.noptrbss` | 32.14 MB | **不占文件**（NOBITS）。大头是 `crypto/internal/fips140/drbg.memory` 的 32 MB 零值数组 |
| `.text` | 14.11 MB | 机器码 |
| `.gopclntab` | 10.70 MB | 函数元数据，panic 栈要用，**去不掉** |
| `.rodata` | 5.93 MB | 字符串 + 内嵌的 `web/dist`（2.9 MB） |
| `.debug_*` + `.symtab`/`.strtab` | ≈12.8 MB | 加 `-s -w` 后全没 |

strip 后 31.42 MB = .text 14.11 + .gopclntab 10.70 + .rodata 5.93 + 其它。
**注意**：`nm` 会把 32 MB 的 `drbg.memory` 算进符号体积，别被这个数字骗了——它在 BSS，不进文件。

**还能压的地方**
1. UPX：gzip 后 12.2 MB，UPX 大概 11–13 MB。代价是启动解压、**杀软误报**（Windows 上尤其容易），只建议 Linux 出包用。
2. 前端 gzip 内嵌：`.rodata` 里 2.9 MB 是原样嵌入的 dist，改成 embed 压缩版 + 响应头 `Content-Encoding: gzip`，约省 2 MB。
3. ECharts 按需引入：`EChart.vue` 现在是 `import * as echarts from 'echarts'`（1.0 MB），换 `echarts/core` + 用到的图表组件约 0.3 MB，省 ~0.7 MB 原始体积（顺带首屏更快）。

**已做**：`bin/` 两个产物重新用 `-s -w` 构建（31.4 / 31.9 MB），并验证 `-version`、登录页、`/api/auth/status` 正常；
`MEMORY.md` 的构建命令补上了 `-ldflags "-s -w"`。

### ECharts 按需引入（已落地）

`components/EChart.vue` 从 `import * as echarts from 'echarts'` 改成：

```ts
import * as echarts from 'echarts/core'
import { LineChart, ScatterChart } from 'echarts/charts'
import { GridComponent, LegendComponent, TooltipComponent } from 'echarts/components'
import { CanvasRenderer } from 'echarts/renderers'
echarts.use([LineChart, ScatterChart, GridComponent, LegendComponent, TooltipComponent, CanvasRenderer])
```

**实测**：ECharts chunk 1035 kB → **488 kB**（gzip 344 → 164 kB），`web/dist` 2.9 MB → 2.4 MB，
linux 产物 31.4 → **30.9 MB**。

**注意点**
- 类型不能用 `echarts.ECharts`（core 不导出），改 `ReturnType<typeof echarts.init>`。
- 全项目只有两处图表：看板趋势图（line + area 线性渐变）、监控历史图（line + scatter），
  组件用到 `grid / tooltip / legend`；`areaStyle` 的渐变是**普通对象** `{type:'linear',...}`，
  不是 `echarts.graphic.LinearGradient`，所以不用额外引 `graphic`。
- **以后新增图表类型必须同步改 `use([])`**，否则该系列会静默不渲染（不报错），很难查。
- Vite 构建不做类型检查，`import { XxxChart }` 写错名字也会构建成功、运行时才炸。
  验证办法：`grep -o '"scatter"' dist/assets/EChart*.js` 看模块有没有真的进包。

**验证**：起服务 + CDP 注入 token，截图看板趋势图（曲线/渐变/网格正常）与监控历史图
（line + 红色 scatter 点都在），页面控制台无报错。
