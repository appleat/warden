## 新增：跨平台构建脚本 build.bat（+ build.ps1）

**需求**：一键交叉编译出各端可执行程序。

**为什么拆成两个文件（重要经验）**
- `.bat` 里写中文会**按 GBK 字节解析**，UTF-8 中文的多字节序列会被拆成命令片段，
  实测报 `'st' 不是内部或外部命令` 这类错，脚本直接跑不起来，`chcp 65001` 也救不了。
- 因此 `build.bat` 保持**纯 ASCII**（36 行壳）：备份/恢复原代码页 → chcp 65001 → 转调 `build.ps1`
  → 透传参数与退出码；中文提示全部放在 `build.ps1`。
- `build.ps1` 必须存成 **UTF-8 with BOM**，否则 PowerShell 5.1 按 ANSI 读会乱码。
- 两个文件都用 **CRLF**（LF-only 的 .bat 在 cmd 下 label/goto 有踩坑风险）。

**功能**：矩阵 windows/linux/darwin × amd64/arm64；`-Version` 注入 ldflags（`main.version` / `main.buildTime`）、
`-SkipWeb` 跳过前端、`-Pack` 打 zip（二进制 + config.yaml，Linux/macOS 才带 deploy）、`-Clean`、`-h`；
位置参数可按平台过滤（`linux` / `linux/arm64`）；未匹配平台或编译失败退出码 1；固定 `CGO_ENABLED=0`。

**验证**：全量构建 6 个产物（每个约 30MB，共 184MB 在 dist/，已加进 .gitignore）；
按魔术字节核对格式 —— ELF64 x86-64/arm64、Mach-O x64/arm64、PE x86-64/arm64 全部正确；
`-Version 1.2.0-test` 构建的 exe 执行 `-version` 显示 `Warden 1.2.0-test (2026-10-26T09:35:13)`；
zip 内含二进制 + config.yaml + deploy/；退出码 0/1 均符合预期；README 已补「Windows 一键交叉编译」章节。

## 修复：容器列表 CPU / 内存显示为 0

**现象**：容器列表新增的 CPU、内存两列在用户环境里恒为 0。

**根因排查（关键结论，改这块务必记住）**
1. Docker 对「不在运行 / cgroup 统计失败」的容器返回的 stats 帧**只有 name/id**，
   字段全 0 但 HTTP 200。旧代码把这种空帧当成功 → 界面显示 0.0% / 0 B，且无任何报错。
   现在 `statsSample.hasStats()` 判空，读到空帧继续读，全空则报错。
2. 单次采样（`stream=0&one-shot=1`）**不会带 precpu_stats**（daemon 的 `GetContainerStats`
   不填 PreCPUStats），CPU 永远算不出来；必须 `stream=1` 读两帧，或 `stream=0`（daemon 会 prime 一帧）。
3. 采集超时原来 4s 偏紧，改为 8s；列表整体上限 15s。
4. 最可能的环境原因：**被管端 Agent 二进制与控制端版本不一致**（旧 agent 不认 `stats=true`，
   返回的对象里根本没有这几个字段，前端就只能显示 0）。

**改动**
- `docker.go`：`ContainerItem` 增加 `stats_error`；`Stat` 增加未导出 `cpuOK` + `CPUAvailable()`；
  `readStats` 跳过空帧、系统 CPU 时间未推进时不认增量；新增 `statsOnce`（one-shot 兜底，
  只保内存）；`collectStats` 流式失败自动退化；Windows 容器给明确错误。
- `Containers.vue`：运行中但拿不到数据时显示 `-`（tooltip 给原因），全部拿不到时表格上方
  出 `el-alert` 提示「版本不一致 / stats 不可用」；详情抽屉同样处理；新增 `inflight` 防轮询叠加。

**验证**（重写 mock Docker，复刻真实行为：帧间隔 1s、首帧 precpu 为空、chunked）
- 正常模式：nginx 8% / 247.0MB·24.1%、redis 10% / 50.0MB·4.9%，exited 显示 `-`，耗时 1.0s
- 空帧模式：接口返回 `stats_error=容器未在运行或无法读取 cgroup 统计`，页面显示 `-` + 提示条
- 经 Agent 反向代理（host=2）同样正确，`/api/containers/:id/stats` 正常
- 新增 3 组单测（空帧报错、单帧保留内存、系统时间不推进不认 CPU），`go test ./...` 全绿
- `dist/` 已重出全平台产物（-Version 1.2.1）

## 修复：端口列叠加 + 资源占用改为异步加载

**现象**：① 刷新列表后端口列越叠越多（elasticsearch 那行出现十几行重复端口）；
② 列表要等 1 秒才出来（资源采集把列表请求堵住了）。

**端口叠加根因**：v-for 的 `:key` 用的是 `p.private_port + p.type`，而 Docker 对同一端口
会按 IPv4/IPv6 各报一条（`0.0.0.0` 与 `::`），key 重复 → el-table 重新 patch 时节点越堆越多。
修法两层：后端 `dedupePorts()` 按 (public/private/type) 合并；前端 `:key` 改用索引 + 最多 2 个
chip，其余进 `+N` 的 tooltip。

**异步加载**：新增 `GET /api/containers/stats`（`docker.Service.StatsFor(ctx, ids)`），
`ids` 为空时算全部 running。前端 `fetchList` 不再带 `stats=true`，列表渲染完成后调 `fetchStats()`
补数据；轮询刷新时把上一次的占用值按 id 合并到新行，避免每 5 秒闪一下「-」；
加载中单元格显示「…」。控制端与 Agent 两端都注册了该路由（`/containers/stats` 与
`/containers/:id` 在 gin 里可共存，未 panic）。

**实测**：列表接口 0.012s（原 1.0s），批量 stats 1.0s；浏览器连点 3 次刷新 + 2 轮静默轮询，
端口 chip 恒为 2 个；打开瞬间 CPU/内存为「…」，约 3 秒后（mock 故意加延迟）填入 8.0% / 247.0MB。
`go test ./...` 全绿（新增 TestDedupePorts）。dist 重出为 1.2.2。

### 修正：初始化服务列表为空 + 切命名空间配置不变（Nacos 1.x 兼容）

用户再次反馈「切命名空间后服务列表、配置列表仍不更新，且初始化后服务列表为空」，怀疑是接口版本兼容问题（让试 v1.0）。
排查确认**两个根因都在后端客户端**，前端没问题。

**根因 1：配置接口认 `tenant`，不认 `namespaceId`（1.x 尤其明显）**
- Nacos 配置接口 `/v1/cs/configs` 的命名空间参数是 `tenant`；命名服务接口才是 `namespaceId`。
- 之前只发 `namespaceId`，1.x 上直接被忽略 → **静默退回 public**，表现就是「切命名空间配置列表纹丝不动」。
- 修法：新增 `setConfigScope(v, ns)`，**同时**写 `tenant` 与 `namespaceId`（新版本也接受 tenant，两者都发无害），
  `Configs / ConfigContent / PublishConfig / DeleteConfig` 全部改用它。

**根因 2：catalog 返回形状不认识时不回落，服务列表就空**
- 原来只在 HTTP 报错（如 404）时才回落到 `/v1/ns/service/list`；但版本差异经常是 **HTTP 200 + 不认识的 JSON 形状**
  （1.x 是 `{totalCount, pageItems}`，2.x 是 `{count, serviceList}`，3.x `service/list` 用 `services`），
  旧代码解析出 0 条就直接返回空列表，不回落 → 「初始化后服务列表为空」。
- 修法：`Services()` 改为返回 `*ServiceList{Items, Total, Source}`；抽出 `parseCatalog(body) (*ServiceList, bool)`，
  形状不认识时 `ok=false` → 调用方回落到 `service/list`（读 `doms` 或 `services` 数组）。
  `count` / `totalCount` 都认，都没有就用 `len(items)`。
- 连带：`internal/api/nacos.go` 的 `nacosServices` 改成读 `list.Items` / `list.Total`。

**顺带修的问题：鉴权错误被下一个端点的 404 覆盖**
- `Namespaces()` 依次试 `/v1/console/namespaces` → `/v3/admin/core/namespace/list`，
  原来只要 `err != nil` 就 `continue`，于是密码错误时 v1 返回 403「认证失败」，
  又被 v3 的真实 404 覆盖成「接口不存在」，误导性极强（`TestWrongPassword` 因此一直是红的）。
- 修法：抽出 `callRaw(ctx, ...) (body, status, err)`（`call` 变成它的包装），
  `Namespaces` 按状态码分流：**404 → 换下一个端点**；**其它 ≥400（鉴权/权限）→ 直接 break**；
  传输层错误也直接 break（两个端点表现一致，重试无意义）。

**新增诊断能力（直接服务「是不是版本兼容问题」）**
- `nacos.Client.Diagnose(ctx, ns) []Probe`，逐个探测 服务端状态 / 就绪检查 / 命名空间列表 /
  catalog services（并注明识别成哪种形状）/ service/list / cs/configs，记录 status + 返回片段（截断 220 字符）。
- 接口 `GET /api/nacos/diagnose` 挂在 `na` 组，并同步注册到 `NewAgentRouter`。
- 前端状态条加「诊断」按钮（`Tools` 图标，注意 `@element-plus/icons-vue` **没有** `Stethoscope`），
  弹出表格展示 接口名 / path / 状态码 / 返回片段，可重新探测。

**验证**
- 新增 `TestV1Compat`：假服务端返回 1.x 的 `{totalCount, pageItems}` 形状，断言
  `Services` 的 `Source == "catalog-1x"` 且解析出 1 条；`Configs` 断言请求里带 `tenant=dev-ns`，
  且服务端「没有 tenant 就返回空」时能正确拿到 dev 的配置（正是用户遇到的现象的反证）。

  `vite build` 通过；`bin/warden-linux-amd64` 已重出。

### 再修：服务列表仍为空（catalog 返回 0 条时不回落）+ 页签顺序

用户反馈「配置列表能显示了，但服务列表还是空的」，并要求**把配置列表放前面、默认显示配置**。

**根因：catalog 可用但返回 0 条时没有回落**
- 上一轮只做到了「形状不认识 → 回落」。但真实场景更常见的是 **HTTP 200 + 形状认识 + 一条都没有**
  （1.x 上 catalog 对某些参数组合就返回 `{count:0,serviceList:[]}`），旧代码认为"解析成功"就直接返回空列表。
- 改法：`Services()` 改成两段式——catalog 解析成功**且有数据**才返回；否则一律再试 `service/list`，
  两边都空才返回 catalog 的结果。service/list 出错时如果 catalog 通了就返回 catalog（不掩盖连通性）。
- 同时：**空值参数不再发送**。原来固定发 `groupName=""` 和 `selector=""`，部分版本会把它当字面量过滤条件
  导致查不到任何服务。现在 `group` / `keyword` 非空才 set；`Diagnose` 的探测参数也同步改成和真实请求一致
  （否则诊断结果没参考价值）。

**可观测性**：`/api/nacos/services` 响应加 `source` 字段（`catalog` / `catalog-1x` / `service-list`），
前端服务表格下方显示「数据来源：xxx」，回落时提示实例数为 -，列表为空时提示去点「诊断」。

**前端页签**：`Nacos.vue` 里两个 `<el-tab-pane>` 整体对调（配置管理在前），`const tab = ref('configs')`。
注意 el-tabs 按 DOM 顺序渲染，只能换块不能只改名。

**验证**：新增 `TestServicesFallbackOnEmpty`（catalog 返回 `{count:0,serviceList:[]}`、
service/list 返回 1 条，断言 `source == "service-list"` 且拿到 1 条，并断言兜底请求不带空 `groupName`）；
`go build` / `go vet` / `go test ./...` 全绿，`vite build` 通过，两个二进制重出。

### 三修：catalog 明明有返回但页面仍为空（宽容解析 + 空结果带原始片段）

用户诊断确认 `/v1/ns/catalog/services` **有返回体**，但页面数据来源显示 `service-list` 且列表为空。
由此可反推：catalog 的返回被 `parseCatalog` 判为"不认识"（或解析出 0 条）→ 回落 service/list → 也是 0 条。

**最大嫌疑：`{code,message,data}` 信封**
- 之前的解析只看顶层 `serviceList` / `pageItems`。若返回被包在 `data` 里，
  就一个键都匹配不到 → 判定"形状不认识" → 页面空白，但接口明明有数据。
- 新增 `unwrapData()`：只要顶层有非字符串的 `data` 字段就剥掉再用。

**解析整体改成宽容模式**（`parseCatalog` → `parseServiceList`，catalog 与 service/list 共用）
- 键名支持 `serviceList` / `pageItems` / `services` / `doms`
- 元素支持对象数组（`serviceDetail`）与字符串数组两种
- 顶层是裸数组也认
- 四种键都不中 → 扫描第一个数组字段（应对键名未知的版本）
- 都中不了才返回 ok=false；HTML / 无数组对象正确判为不认识

**空结果不再"静默为空"**
- `ServiceList` 增加 `Hint` 字段：只在一条都没查到时填充，
  内容为 `catalog: <原始片段> ｜ service/list: <原始片段>`（复用 `snippet()` 截断 220 字符）。
- 接口返回 `hint`，前端服务表格下方在列表为空且 hint 非空时直接显示（橙色 mono），
  **用户不用再去点诊断就能把真实返回念出来**，终结来回猜形状的循环。
- `Diagnose` 也改用同一个解析器，两条服务接口都标注「命中键 X，本页 N 条 / 共 M 个」。

**验证**：新增 `TestParseServiceListShapes`（7 种形状含 data 信封、doms、services、裸数组、未知键名扫描；
3 种反例 HTML / `{"message":"ok"}` / 空串必须判为不认识）。`go build`/`go vet`/`go test ./...` 全绿，
`vite build` 通过，两个二进制重出。

### 四修（真凶）：triggerFlag 是字符串，整个数组解析失败

用户贴出了真实返回：
```json
{"count":4,"serviceList":[{"name":"ybs-gateway","groupName":"dev","clusterCount":1,
  "ipCount":2,"healthyInstanceCount":2,"triggerFlag":"false"}, ...]}
```

**根因**：`serviceDetail.TriggerFlag` 写成了 `bool`，而服务端返回的是**字符串** `"false"`。
Go 的 `json.Unmarshal` 遇到类型不匹配会返回 `UnmarshalTypeError`，**整个 serviceList 数组解析失败**
→ 判定"形状不认识" → 回落 service/list（该服务端这里返回 `{"count":0,"doms":[]}`）→ 列表为空。
典型症状：**接口有数据、页面一条都没有**。
- 附带：健康实例数在这台服务端叫 **`healthyInstanceCount`** 不是 `healthyCount`，
  就算解析成功健康数也会是 0。

**改法（重要经验）**
- `serviceDetail` 的**数值与布尔字段全部改成 `any`**，用 `toInt()` / `toFloat()` / `truthy()` 转换；
  同时补上 `healthyInstanceCount` 作为 `healthyCount` 的备选。
  **结论：对接 Nacos 这种多版本 OpenAPI，结构体字段别直接写 bool/int，一律 any + 转换函数，
  否则一个字段类型不一致就整片数据丢失，且没有任何报错。**
- 实例列表 `Instances` 的同款风险一并修掉：`port/healthy/enabled/ephemeral/weight` +
  `reachProtectionThreshold/triggerFlag` 全改 `any`，`metadata` 改 `map[string]any` 再用 `toStr()` 转回字符串。

**验证**：新增 `TestServicesRealPayload`（直接喂用户那段真实 JSON，断言 4 个字段都对、
`triggerFlag="false"` 解析为 false）、`TestServicesNoFallbackOnRealShape`（复现 catalog 有数据、
service/list 返回 0 条的场景，断言 `source=="catalog"` 且不回落）、
`TestInstancesTypeTolerance`（实例字段全用字符串喂一遍，含 metadata 里的数字值）。
`go build` / `go vet` / `go test ./...` 全绿，`vite build` 通过，两个二进制重出。

### 修复：服务列表按分组过滤无效（键名是 groupNameParam）

用户抓了 Nacos 客户端的真实请求：
```
/nacos/v1/ns/catalog/services?hasIpCount=true&withInstances=false&pageNo=1&pageSize=10
  &serviceNameParam=&groupNameParam=test&namespaceId=test
```
**分组过滤的键名是 `groupNameParam`，不是 `groupName`** —— 我们一直只发 `groupName`，
服务端直接忽略，于是"按分组过滤"等于没过滤（也不报错）。

**改法**：`Services()` 的参数照抄控制台请求
- 非空分组**同时发 `groupName` 与 `groupNameParam`**（值相同，老版本有的认 `groupName`，互不冲突）
- 加 `hasIpCount=true`（控制台一直带，保证返回体里有实例数）
- 空值依旧不发（部分版本会当字面量过滤条件）
- `Diagnose` 的探测参数同步对齐，否则诊断结果没参考价值

**验证**：新增 `TestServicesGroupFilterParams`（服务端只认 `groupNameParam` 的假实现，
断言过滤时两个键都在、且 `hasIpCount=true`；不过滤时两个键都不能出现）。
`go build`/`go vet`/`go test ./...` 全绿，`vite build` 通过，两个二进制重出。

### 修复：文件管理刷新报 `open /[object PointerEvent]`

`FileBrowser.vue` 全宽工具栏刷新按钮写的是 `@click="load"`，而 `load(p?: string)` 带参数 ——
Vue 会把 **PointerEvent 当作第一个实参**传进去，于是 `p ?? path.value` 拿到事件对象，
请求变成 `/api/files?path=[object PointerEvent]`，后端拼路径后 `open /[object PointerEvent]` 报错。
紧凑工具栏那颗写的是 `@click="load()"`，所以只有文件管理整页的刷新会炸。

**修法**：改成 `@click="load()"`。

**顺带全量排查**：把所有 `@xxx="bareIdentifier"`（不带括号的处理器）与对应函数签名对了一遍，
确认其它带参处理器都是**故意**接收事件/值的，没问题：
`onHostChange(id)` ← el-select 的 change 值、`onCommand(cmd)` ← el-dropdown 的 command、
`onFiles(e: Event)` ← input 的 change、`startResize(e: MouseEvent)` ← mousedown、
`toggleFw(val)` ← el-switch 的 change。

### 导航重构：系统管理下拆三个二级菜单

**需求**：文件管理挪进系统管理；系统管理页面里的防火墙也拆成二级菜单。
最终结构（顺序按需求）：`系统管理 → 文件管理 / 防火墙管理 / SSH 终端管理`，**功能不变**。

**做法**
- `router.ts`：新增 `system/firewall`、`system/ssh`、`system/terminal` 三条路由，**都指向 `System.vue`**；
  旧的 `system` 保留为 `redirect: '/system/firewall'`（避免旧书签 404）。
  `files` 路由路径不动（只挪导航项）。
  注意 `system/ssh` **必须建**，否则反向同步时 `router.replace('/system/ssh')` 会落到 404 → 跳看板。
- `MainLayout.vue`：`系统管理` 改成带 `children` 的父项（`icon: Monitor`，无 path），
  删掉原来独立的「文件管理」项与 `FolderOpened` 图标导入（已无引用）。
- `System.vue`：页签由路由决定 —— `tabOf(path)`（`/terminal`→terminal、`/ssh`→ssh、否则 firewall），
  `watch(route.path)` 更新 tab；**再反向 `watch(tab)` 用 `router.replace` 同步地址**，
  这样手动点页签时左侧高亮也跟着走（用 replace 不堆历史；两边都有 `route.path !== want` 守卫，不会互相触发死循环）。
  页面内的三个页签全部保留，功能没动。

**验证**：`vite build` 通过（`vue-tsc` 本机没装，跳过类型检查），两个二进制重出。

**经验（通用）**：Vue 模板里 `@click="fn"` 与 `@click="fn()"` **不等价**——前者会把事件对象注入第一个形参。
带参数的函数一律写成 `fn()` 或显式传参。

**经验：Nacos 多版本兼容的三条硬规则**
1. 配置接口必须带 `tenant`（顺带发 `namespaceId` 无害）。
2. 任何列表解析都要「形状不认识 → 回落」，不能只看 HTTP 状态码。
3. 多端点依次尝试时，**不要把鉴权/权限错误当成「该端点不存在」**，否则错误信息会被后来的 404 覆盖。
